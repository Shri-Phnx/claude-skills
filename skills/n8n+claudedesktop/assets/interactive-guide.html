Phase 1 — n8n setup
Enable MCP and get your token

Enable MCP access n8n settings

1Open n8n → go to Settings → Instance-level MCP
2Toggle "Enable MCP access" to ON (requires admin/owner role)
3Click "Connection details" (top-right) → switch to Access Token tab
4Copy your token immediately — it is redacted after you leave this page
Token is a long JWT starting with "eyJ...". Copy the entire string — do not include any quotes around it.

Phase 1 — n8n setup
Create and expose a compatible workflow
Only Chat, Webhook, Form, or Schedule triggers work with MCP. Manual Trigger is NOT compatible.

Create the test workflow

1Go to Workflows → New Workflow
2Click "+" → choose Chat trigger (When chat message received) → select it
3Click "+" again → add Edit fields (Set) node → connect it to Chat trigger → click the Edit fields (Set) node to open it → under Fields to Set, click Add field → set Name as message and Value as MCP is working!
4Click the workflow name in the top-left header → rename it to MCP Test
5Press Ctrl+S (Windows) / Cmd+S (Mac) to save → click dropdown arrow next to Save → select Publish

Expose workflow to MCP required

1Go to Overview → find MCP Test in your workflows list
2Click the ... (3 dots) menu next to MCP Test → select Enable MCP access
3Go to Settings → Instance-level MCP to confirm MCP Test appears in the table ✓
Optional: click (...) → Edit description to help Claude identify what the workflow does.

Step 1 — Install mcp-remote one-time only

1Open terminal
2Run:
npm install -g mcp-remote
Node.js v18 or newer is required. If npm is not found, download from nodejs.org first.
Success = "added 82 packages". The command mcp-remote --version will error — this is normal, not a problem.

Phase 2 — Claude Desktop setup
Update the config file and restart Claude

Step 3 — Add n8n-local to config

1Add the n8n-local block inside mcpServers — do not delete any existing entries
2Replace <YOUR_N8N_TOKEN_HERE> with your full token. No angle brackets. No quotes around the token. Example format:
"Authorization:Bearer eyJhbGciOiJIUzI1NiIs..."
Space after "Bearer" is required. Paste the full "eyJ..." string directly — no quotes around it.
Share your existing config file content in chat and Claude will produce the complete updated file for you.

Step 4 — Restart Claude Desktop

1Save the config file
2Fully quit Claude Desktop — do not just close the window. Also quit from the system tray (right-click tray icon → Quit)
3Reopen Claude Desktop
4Go to Settings → Connectors — n8n-local should appear without a red "failed" badge

Troubleshoot quick reference

!Server disconnected → run npm install -g mcp-remote as admin → quit from system tray → reopen
!Not valid MCP config → use mcp-remote command format, not "type":"http"
!No workflows showing → must use Chat/Webhook trigger AND be Published
!401 Unauthorized → no quotes around token, space after "Bearer", full eyJ... string
Test failed or unexpected result?
Security: rotate your n8n token regularly — Settings → Instance-level MCP → Connection details → Generate new token. Update config and restart Claude Desktop.
Step 7 — Adding new workflows to MCP
Connect any new n8n workflow to Claude
Follow these steps every time you build a new workflow. No config file changes or Claude Desktop restarts needed.

Checklist — repeat each time no restart needed

1Build workflow with compatible trigger: Chat, Webhook, Form, or Schedule. Never Manual Trigger.
2Press Ctrl+S (Windows) / Cmd+S (Mac) to save
3Click dropdown arrow next to Save → select Publish. Must be Published, not just saved.
4Go to Overview → find your workflow → click ... (3 dots) → select Enable MCP access
5Go to Settings → Instance-level MCP → confirm workflow appears in table
6Click ... → Edit description and write what the workflow does. Example: Sends daily job alert digest from LinkedIn and Indeed RSS feeds
7Test in Claude Desktop: "List all workflows in my n8n instance" → new workflow should appear
8Trigger it: "Execute the [your workflow name] workflow"

Common mistakes to avoid do not do these

xUsing Manual Trigger — workflow will not appear in the MCP enable dialog
xForgetting to Publish — saved-only workflows do not appear in MCP
xSkipping Enable MCP access — workflows are hidden from MCP by default
xEditing config file or restarting Claude Desktop — only needed once during initial setup
